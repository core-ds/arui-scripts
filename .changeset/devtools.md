Панель отладки модулей.

Загрузчик пишет диагностику каждой попытки загрузки в публичный версионированный контракт
`globalThis.__ARUI_DEVTOOLS__.modules`: источник, версию, контейнер, абсолютные url ресурсов,
тайминги стадий и ошибки — включая те, что раньше не доходили даже до `onError`. Данные
дублируются в `sessionStorage` и переживают перезагрузку страницы. В прод-сборке сбор по
умолчанию спит и не создаёт ни глобала, ни записей — включается ключом `arui:devtools`
в `localStorage`; в dev-сборке включён всегда. Читать контракт может кто угодно:
`__ARUI_DEVTOOLS__.modules.getSnapshot()`.

Новый пакет `@alfalab/scripts-devtools` показывает эти данные панелью прямо на странице.
Открывается по `Ctrl/Cmd+Shift+M` или кликом по бейджу в углу. Вкладка «Модули» — таблица
попыток загрузки: водопад стадий с подсказками, ресурсы с Resource Timing, стадия, сообщение
и стек ошибки. «События» — лог загрузчика с фильтром: виден порядок событий между модулями.
«Share scope» — содержимое скоупов с подсветкой проблем: несколько версий одного пакета
и `singleton` с расходящимися мажорами. Панель помнит открытость и активную вкладку в пределах
вкладки браузера. UI написан на React 19, забандленном в lazy-чанк панели приватной копией:
у пакета по-прежнему ноль зависимостей, в share scope и в основной бандл приложения этот React
не попадает. Внешне панель следует дизайн-системе core-components, но не зависит от неё.

`arui-scripts` подмешивает панель в клиентский бандл сам — новый ключ конфигурации
`devtools: 'dev' | 'always' | 'off'`, по умолчанию `'dev'`. Ключ управляет только попаданием
кода в сборку, видимостью — `localStorage`. В основной бандл попадает только хоткей с бейджем,
сама панель уезжает в отдельный чанк и грузится при открытии.

Побочно: `ModuleResources` получил необязательное поле `manifestUrl`, а `resolveResourceUrl`
стал экспортируемым. `LifecycleHooks` не тронуты — они остаются публичным API для метрик.
