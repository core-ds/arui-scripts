# Исправления suspense module mounter

## Цель

Исправить две регрессии в новых клиентах монтирования: выбор SSR payload при нескольких
экземплярах одного модуля и освобождение ресурсов `createLazyMounter`.

## SSR payload

`createSsrMounter` должен создавать клиентский loader в контексте конкретного
`instanceId`. Его embedded fetcher получает тот же `instanceId`, что и серверный
`data-module-instance`, и поэтому считывает только payload соответствующего экземпляра.
Loaders кэшируются по `instanceId`; экземпляры с разными идентификаторами не должны
разделять payload или `moduleState`.

## Lifecycle lazy mounter

После успешного `mount` компонент хранит функцию очистки. При размонтировании он вызывает
`module.unmount(target)` и `result.unmount()`. При изменении `runParams` без `update`
предыдущий экземпляр сначала размонтируется, затем монтируется с новыми параметрами.
Если `update` есть, используется только `update`.

## Проверка

Будут добавлены регрессионные тесты: два SSR-инстанса с разными payload и lifecycle
`createLazyMounter` при обновлении и размонтировании. Затем запускаются релевантные Jest
тесты и проверка TypeScript/сборки пакета в объёме, доступном в репозитории.
