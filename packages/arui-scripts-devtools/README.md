# @alfalab/scripts-devtools

Расширение Chrome для отладки модулей `arui-scripts`. Добавляет в DevTools вкладку **ARUI**,
где видно, что происходило с каждым загруженным модулем: откуда его брали, какой манифест
прочитали, сколько заняла каждая стадия, что лежит в share scope и на чём всё сломалось.

Пользовательская документация — [расширение для отладки модулей][docs].
Здесь только то, что нужно тем, кто с этим пакетом работает напрямую.

## Как выглядит

Вкладка «Модули» — таблица попыток загрузки, строка раскрывается в подробности: водопад стадий
с паузами между ними и ресурсы с Resource Timing.

![Вкладка «Модули» с раскрытой загрузкой](https://raw.githubusercontent.com/core-ds/arui-scripts/master/packages/arui-scripts-devtools/docs/panel-modules.png)

Ради этого кадра расширение и написано: стадия, на которой всё сломалось, сообщение и стек —
вместо `Failed to load module` в консоли.

![Раскрытая ошибка загрузки](https://raw.githubusercontent.com/core-ds/arui-scripts/master/packages/arui-scripts-devtools/docs/panel-error.png)

Вкладка «События» — лог загрузчика с фильтром: видно порядок между модулями, кто кого ждал.

![Вкладка «События»](https://raw.githubusercontent.com/core-ds/arui-scripts/master/packages/arui-scripts-devtools/docs/panel-events.png)

Вкладка «Share scope» — что реально лежит в скоупах, с разбором проблем.

![Вкладка «Share scope»](https://raw.githubusercontent.com/core-ds/arui-scripts/master/packages/arui-scripts-devtools/docs/panel-share-scope.png)

## Установка

```bash
yarn workspace @alfalab/scripts-devtools build
```

`chrome://extensions` → **Режим разработчика** → **Загрузить распакованное расширение** →
`packages/arui-scripts-devtools/build/extension`.

После пересборки жмите «Обновить» на карточке расширения и перезапускайте DevTools: вкладки
заводятся в момент их открытия.

## Разработка

```bash
yarn build && yarn test
```

Что где лежит:

| Файл                   | Зачем                                                                        |
| ---------------------- | ---------------------------------------------------------------------------- |
| `extension/manifest.json` | MV3-манифест; разрешений не просит вовсе — хватает `chrome.devtools`       |
| `extension/devtools.*`    | страница-регистратор: заводит вкладку в DevTools и больше ничего не делает |
| `extension/panel.*`       | документ вкладки: монтирует React-панель в shadow root                     |
| `extension/source.ts`     | мост к странице: опрос через `inspectedWindow.eval`                        |
| `extension/snapshot-expression.ts` | то самое выражение, которое исполняется на чужой странице         |
| `panel/`               | React-компоненты вкладок, водопад, подсказки, стили                          |
| `utils/`               | разбор снимка скоупа, форматирование, Resource Timing, состояние панели      |
| `types.ts`, `constants.ts` | контракт `__ARUI_DEVTOOLS__` на чтение и все константы пакета            |
| `scripts/`             | сборка расширения (`bundle-extension.js`) и генератор html для скриншотов     |

## Что стоит знать, если правишь этот пакет

-   **Данные приходят только через контракт.** Расширение живёт в своём документе и к странице
    имеет ровно один доступ — `chrome.devtools.inspectedWindow.eval`, который возвращает
    структурный клон. Ничего, кроме сериализуемых данных, оттуда прийти не может, поэтому
    и контракт `__ARUI_DEVTOOLS__` состоит только из данных.
-   **`__webpack_share_scopes__` расширению недоступен в принципе.** Это свободная переменная
    бандлера, видимая только изнутри бандла приложения. Снимок скоупа кладёт в контракт
    загрузчик (`@alfalab/scripts-modules`), а расширение его только разбирает —
    `utils/share-scope.ts`.
-   **Выражение для `eval` пишется на ES5 и без синтаксического сахара**: исполнять его будет
    движок чужой страницы. Собрано оно из тех же констант, что и остальной пакет, чтобы ключ
    и версии не разъехались, и обёрнуто в `try` — бросок отсюда прилетел бы в консоль чужого
    приложения.
-   **Опрос молчит, пока ответ не изменился.** Страницу спрашивают дважды в секунду, и почти
    всегда ответ тот же самый; перерисовывать на это панель значит дёргать её на ровном месте.
-   **Панель монтируется в shadow root**, хотя изолировать её тут не от чего: документ наш
    целиком. Так у стилей остаётся один путь — `:host` с токенами работает как есть,
    а `extension/panel-styles.css` добавляет только геометрию под вкладку DevTools.
-   **Внешний вид — по дизайн-системе [core-components][core-components], но без зависимости
    от неё.** Цвета берутся из тёмной палитры (`--color-dark-*`), кнопки, вкладки и статусы
    повторяют геометрию соответствующих компонентов. Переменные названы по именам дизайн-системы
    и продублированы запасными значениями. Новый цвет мимо токена ловит тест в `styles.tests.ts`.
    Правила `stylelint-core-vars` в `panel/styles.css` отключены осознанно — и по этому файлу
    нельзя запускать `stylelint --fix`, его фиксер игнорирует disable-комментарии.

## Контракт данных

Расширение ничего не собирает само — оно читает публичный контракт `__ARUI_DEVTOOLS__`, который
наполняет `@alfalab/scripts-modules`. Типы контракта на чтение продублированы внутри пакета
(`src/types.ts`) намеренно: расширение читает стор произвольной версии загрузчика,
и договариваться с ним приходится по номеру версии, а не по общим типам.

Описание контракта — в [документации][contract].
