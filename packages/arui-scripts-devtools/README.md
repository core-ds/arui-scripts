# @alfalab/scripts-devtools

Панель отладки модулей для приложений на `arui-scripts`. Показывает, что происходило с каждым
загруженным модулем: откуда его брали, какой манифест прочитали, сколько заняла каждая стадия,
что лежит в share scope и на чём всё сломалось.

Пользовательская документация — [панель отладки модулей][docs].
Здесь только то, что нужно тем, кто с этим пакетом работает напрямую.

## Как выглядит

Вкладка «Модули» — таблица попыток загрузки, строка раскрывается в подробности: водопад стадий
с паузами между ними и ресурсы с Resource Timing.

![Вкладка «Модули» с раскрытой загрузкой](https://raw.githubusercontent.com/core-ds/arui-scripts/master/packages/arui-scripts-devtools/docs/panel-modules.png)

Ради этого кадра панель и написана: стадия, на которой всё сломалось, сообщение и стек — вместо
`Failed to load module` в консоли.

![Раскрытая ошибка загрузки](https://raw.githubusercontent.com/core-ds/arui-scripts/master/packages/arui-scripts-devtools/docs/panel-error.png)

Вкладка «События» — лог загрузчика с фильтром: видно порядок между модулями, кто кого ждал.

![Вкладка «События»](https://raw.githubusercontent.com/core-ds/arui-scripts/master/packages/arui-scripts-devtools/docs/panel-events.png)

Вкладка «Share scope» — что реально лежит в `__webpack_share_scopes__`, с разбором проблем.

![Вкладка «Share scope»](https://raw.githubusercontent.com/core-ds/arui-scripts/master/packages/arui-scripts-devtools/docs/panel-share-scope.png)

## Обычный способ подключения — никакой

`arui-scripts` сам подмешивает энтрипоинт панели в клиентский бандл, если в конфигурации
не выключен ключ [devtools][settings]. Ставить пакет руками
и импортировать что-либо не нужно.

Открывается панель по `Ctrl/Cmd+Shift+M` или кликом по бейджу в углу.

Видимостью управляет ключ `arui:devtools` в `localStorage` — значения `1` / `true` / `on`
включают, `0` / `false` / `off` выключают. Флаг сильнее сборки в обе стороны: им открывают панель
в прод-сборке на стенде и им же выключают её в разработке, если мешает. Без флага панель есть
только в dev-сборке. Тем же ключом включается и сбор данных в `@alfalab/scripts-modules`,
поэтому семантика у них общая — иначе получилась бы открытая панель без данных.

## Ручное подключение

Если панель нужна там, где автоинжект не работает (своя сборка, другой бандлер), есть два входа.

```ts
// вешает хоткей и бейдж, код панели грузит отдельным чанком только при открытии
import { installDevtools } from '@alfalab/scripts-devtools';

const uninstall = installDevtools();
```

```ts
// монтирует панель сразу, без хоткея и бейджа
import { mountDevtools } from '@alfalab/scripts-devtools';

const unmount = mountDevtools();
```

Пакет экспортирует и то, из чего панель собрана: `watchModulesStore`, `readShareScopes`,
`readResourceTiming` и типы контракта. На них можно собрать свою панель или отправлять
диагностику в мониторинг.

## Почему тут нет React

Энтрипоинт панели инжектится **абсолютным путём из `node_modules` самого `arui-scripts`**.
Значит `import 'react'` внутри панели резолвился бы от дерева `arui-scripts`, а не приложения,
и второй React появился бы по построению — со всеми вытекающими `Invalid hook call`. Плюс панель
попала бы в тот самый share scope, за которым она наблюдает.

Поэтому UI собран на голом DOM, а у пакета **ноль зависимостей и ноль peer-зависимостей**.
Панель монтируется в свой хост-элемент с shadow root: её стили не текут наружу, а стили приложения
не ломают её.

## Разработка

```bash
yarn build && yarn test
```

Что где лежит:

| Файл                | Зачем                                                                     |
| ------------------- | ------------------------------------------------------------------------- |
| `contract.ts`       | копия публичного контракта на чтение — импортировать типы из соседа нельзя |
| `store-client.ts`   | подписка на стор, разбор версии, состояния `ready` / `waiting` / `unsupported` |
| `install.ts`        | хоткей и бейдж; лежит в основном бандле, поэтому сюда тащим только нужное  |
| `mount.ts`          | хост, shadow root, монтирование и снятие панели                           |
| `auto.ts`           | энтрипоинт для автоинжекта из `arui-scripts`                              |
| `ui/`               | вкладки, таблицы, водопад, стили                                          |
| `scripts/`          | генератор html для скриншотов в `docs/`                                   |

Грабли, на которые наступают все: **`yarn build` делает `rm -rf build`**, а `arui-scripts`
резолвит энтрипоинт панели один раз, когда собирает конфиг — то есть на старте dev-сервера.
Снести под работающим сервером файл, на который он ссылается, значит выкинуть панель из бандла:
приложение продолжает собираться и работать, в консоли ни ошибки, просто ни бейджа, ни хоткея.
`touch` по энтрипоинту приложения этого **не** чинит — пересборка проходит успешно и без панели.

Поэтому после сборки пакета dev-сервер примера надо перезапускать:

```bash
yarn workspace example start
```

Стор появляется только при первой загрузке модуля, а панель могут открыть раньше, поэтому
`watchModulesStore` опрашивает глобал раз в 500 мс, пока стора нет, и переходит на подписку,
как только он появился. Бейдж при этом ждёт события `arui:devtools:ready` от загрузчика: понять
на этапе сборки, грузит ли приложение модули, нельзя — хост-потребитель их не конфигурирует.

Скриншоты в `docs/` собираются из настоящей панели на подготовленных данных — так в кадр попадают
состояния, которых в примере обычно нет: незавершённая загрузка, ошибка, расхождение версий.
Данные и время в скрипте зафиксированы, поэтому html воспроизводится байт в байт. **А вот png —
нет:** кодировщик браузера даёт разные байты при одинаковой картинке, так что перегенерация
без правок вёрстки добавит в историю бессмысленный бинарный диф. Обновлять после правок вёрстки:

```bash
yarn build && node scripts/render-screenshots.js
```

Скрипт кладёт html рядом с картинками и печатает готовые команды, снимающие с них png
(у каждого кадра своя высота, чтобы обрезалось по границе строки). Снять можно любым браузером,
не обязательно тем, что в подсказке.

## Что стоит знать, если правишь этот пакет

-   **`exports` ведёт на ESM-сборку.** У CJS-сборки `import()` превращается в `require`, который
    бандлер не сплитит, и панель уезжает в основной бандл целиком вместо отдельного чанка.
    По той же причине `arui-scripts` резолвит энтрипоинт через `package.json` пакета, а не через
    `require.resolve('@alfalab/scripts-devtools/auto')` — node отдал бы CJS.
-   **`build/esm` не помечается `{"type": "module"}`.** Маркер выглядит правильным, но `tsc`
    с `moduleResolution: bundler` эмитит специфаеры без расширений, и с ним node и бандлеры
    перестают резолвить соседние файлы. Соседний `@alfalab/scripts-modules` собирается тем же
    tsconfig и маркера не имеет — отклоняться от него не надо.
-   **Внешний вид — по дизайн-системе [core-components][core-components], но без зависимости
    от неё.** Цвета берутся из тёмной палитры (`--color-dark-*`), кнопки, вкладки и статусы
    повторяют геометрию соответствующих компонентов. Импортировать `@alfalab/core-components/vars`
    нельзя — это зависимость, которая приедет в бандл приложения, — поэтому переменные названы
    по именам, а значения продублированы запасными: `var(--color-dark-bg-primary, #0b1f35)`.
    Подключило приложение вары — панель возьмёт его палитру, не подключило — свою копию.
    Размеры (`--gap-*`, `--border-radius-*`) намеренно вписаны числами: имена слишком общие,
    и чужое значение из приложения развалило бы вёрстку, тогда как чужой цвет просто окажется
    другим. Новый цвет мимо токена ловит тест в `styles.tests.ts`.
-   **Хост-элементу нельзя ставить `data-parent-app-id`** — по этому атрибуту загрузчик модулей
    вычищает ресурсы модуля из DOM и заодно снесёт панель.
-   **`__webpack_share_scopes__` — свободная переменная бандлера**, а не свойство `window`.
    Проверять её можно только через `typeof`. Вызывать `get()` у записи скоупа нельзя: это исполнит
    шаренный модуль, то есть панель своим существованием изменит поведение приложения.
-   **`process.env.NODE_ENV` читается буквально.** Проверка `typeof process !== 'undefined'` перед
    этим ломает подстановку бандлера: в браузерном бандле глобального `process` нет, и панель
    не включится вовсе. Юнит-тесты этого не ловят — в jest `process` есть.

## Контракт данных

Панель ничего не собирает сама — она читает публичный контракт `__ARUI_DEVTOOLS__`, который
наполняет `@alfalab/scripts-modules`. Типы контракта на чтение продублированы внутри пакета
(`src/contract.ts`) намеренно: импорт типов из `scripts-modules` сделал бы его зависимостью,
а договариваться с чужой версией загрузчика всё равно приходится по номеру версии, а не по типам.

Описание контракта — в [документации][contract].
