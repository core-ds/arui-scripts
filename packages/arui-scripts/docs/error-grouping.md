# Ошибки сборки

При запуске `start` или `start:prod` ошибки клиентской и серверной сборки выводятся отдельно. Внутри каждого блока ошибки собраны по категориям: например, проблемы с импортами попадут в `Module Error`, а синтаксис стилей — в `CSS Error`.

Команда `build` показывает первую ошибку с подробностями и подсказками, без группировки.

## Как читать вывод

Допустим, в компоненте есть импорт `./Button`, но сборщик не может найти этот файл. В терминале появится примерно такой блок:

```text
Client: Build failed

Module Error:
  • Module not found: Error: Can't resolve './Button'
    at src/components/index.tsx:5
    Suggestions:
      - Check that the file path is correct
```

Здесь `Client` означает, что ошибка возникла при сборке клиентского кода. Под сообщением указан файл и, если сборщик передал эту информацию, строка и колонка. Многострочные сообщения и фрагменты исходного кода сохраняются целиком.

В `Suggestions` перечислены возможные способы исправления. Они подбираются по тексту ошибки и не всегда указывают на её точную причину. Начните с самого сообщения и указанного в нём места в коде.

Если ошибок много, в каждой категории будут показаны первые пять, а у каждой ошибки — до двух подсказок. Предупреждения выводятся отдельно; текст и расположение каждого показанного предупреждения тоже сохраняются полностью.

## Если не находится импорт

Подсказка зависит от того, что вы импортируете:

- Для `./Button` или абсолютного пути предлагается проверить путь к файлу.
- Для npm-пакета предлагается проверить, установлен ли он, и при необходимости установить его. Например, для `lodash/debounce` команды будут относиться к пакету `lodash`, а для `@scope/package/subpath` — к `@scope/package`.
- Для путей с префиксами `@/`, `~/` и `#` предлагается проверить `paths` в `tsconfig.json`, `resolve.alias` или `imports` в `package.json`.

Например, если не найден `lodash`, подсказка выглядит так:

```text
Suggestions:
  - Check if the package is installed
    Run: npm ls lodash
  - Install the package
    Run: npm install lodash
```

Команды приведены для npm. Если проект использует другой пакетный менеджер, выполните соответствующую команду в нём.

Alias без специального префикса, например `components/Button`, нельзя надёжно отличить от имени пакета. Если для такого импорта предлагается установка, сначала проверьте настройки alias.

Если модуль найден, но в нём нет нужного экспорта, сообщение Rspack `export ... was not found` также попадёт в `Module Error`. Ошибки с кодами TypeScript, например `TS2307`, выводятся в `TypeScript Error`.

## Настройка watch-вывода

Чтобы оставить только ошибки и убрать цвета, добавьте `stats` в файл `arui-scripts.overrides.js`:

```javascript
module.exports = {
    stats: () => ({
        all: false,
        errors: true,
        colors: false,
    }),
};
```

Если файл уже есть, добавьте этот ключ к существующим overrides. Подробнее о формате файла — в [документации по overrides](overrides.md).

Параметры `errors` и `warnings` управляют показом ошибок и предупреждений. Можно также вернуть строковый preset Rspack, например `'errors-only'`. Чтобы полностью отключить группированный вывод, верните `false`, `'none'` или `{ all: false }`.

`colors: false` убирает цвет и из оформления arui-scripts, и из исходных сообщений сборщика. Скрытие ошибки влияет только на вывод: сообщение об успешной сборке вместо неё не появится.

Остальные диагностические параметры `stats` передаются Rspack при получении сообщений. При этом группированный вывод не показывает таблицы модулей и файлов сборки, их размеры или время сборки.

### Если статистика всё ещё выводится

Клиентский dev-middleware может печатать собственную статистику в дополнение к сообщениям arui-scripts. На неё override `stats` не влияет: её нужно настраивать отдельно через `devServer.devMiddleware.stats` в override `devServer`.
