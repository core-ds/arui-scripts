# Панель отладки модулей

Когда модуль не загрузился, а в консоли только `Failed to load module`, разбираться приходится
по крупицам: откуда его вообще пытались взять, какой манифест прочитали, дошло ли дело до
module federation, что лежит в share scope. Панель отладки показывает всё это в одном месте.

Панель — это пакет [@alfalab/scripts-devtools][package], который `arui-scripts` сам подмешивает
в клиентский бандл.

![Панель отладки модулей](https://raw.githubusercontent.com/core-ds/arui-scripts/master/packages/arui-scripts-devtools/docs/panel-modules.png)

## Как открыть

`Ctrl+Shift+M` (на маке ещё и `Cmd+Shift+M`) или клик по бейджу `arui devtools` в правом нижнем
углу. Закрывается тем же хоткеем, крестиком или `Esc`. У `Esc` два исключения: в непустом поле
фильтра он сначала очищает поле, а на открытой подсказке — гасит подсказку; панель в обоих
случаях остаётся.

В dev-сборке панель доступна сразу. В прод-сборке она молчит, пока её не включат вручную:

```js
localStorage.setItem('arui:devtools', '1');
```

Этот же ключ работает и в обратную сторону — `'off'` выключает панель в разработке, если она
мешает. Значения: `1`, `true`, `on` включают, `0`, `false`, `off` выключают.

Ключ управляет не только видимостью панели, но и сбором данных для неё — см.
[Цена в проде](#цена-в-проде). Читается он один раз при старте страницы, поэтому менять его
нужно вместе с перезагрузкой.

Панель помнит, была ли она открыта и на какой вкладке, и возвращается в том же виде после
перезагрузки страницы. Помнит в пределах вкладки браузера (`sessionStorage`, ключ
`arui:devtools:panel`), так что в соседних вкладках она не всплывёт.

## Настройка devtools

Ключ `devtools` в [arui-scripts.config](settings.md#devtools) управляет тем, попадёт ли код панели
в сборку. Видимостью он не управляет — за неё отвечает `localStorage`, см. выше.

| Значение   | Что делает                                                                                        |
| ---------- | ------------------------------------------------------------------------------------------------- |
| `'dev'`    | Подмешивать только в dev-сборку. В прод-бандле кода панели нет вовсе. **По умолчанию**            |
| `'always'` | Подмешивать и в прод-сборку. Нужно для стендов: собрано как прод, но панель можно включить руками |
| `'off'`    | Не подмешивать никогда                                                                            |

В основной бандл попадает только небольшая eager-часть — хоткей и бейдж. Сама панель (таблица,
share scope, стили) лежит в отдельном чанке и грузится только в момент открытия.

Панель подмешивается **только в основной клиентский конфиг**. В отдельную сборку модулей
(`modules.options.useSeparateBuild`) и в конфигурации compat-модулей она не попадает: там нет
приложения, в котором её показывать.

С `disableModulesSupport: true` панель в сборку не попадает вовсе: проект сам разбирается
с module federation, и загрузчику, за которым панель наблюдает, там взяться неоткуда.

По остальным приложениям на этапе сборки решить нельзя: хосту-потребителю ключ `modules`
не нужен, модули он подключает в рантайме. Поэтому бейдж в углу появляется не сразу, а когда
на странице действительно случилась первая попытка загрузить модуль. Если модулей нет,
бейджа не будет — но хоткей работает всегда, так что открыть панель и убедиться в этом можно.

## Цена в проде

Данные для панели собирает не она сама, а `@alfalab/scripts-modules`: сбор живёт внутри загрузчика
модулей и от настройки `devtools` не зависит — та управляет только кодом панели.

В прод-сборке сбор по умолчанию **спит**. Он стоит на горячем пути загрузки каждого модуля
(больше трёх десятков обновлений стора на один модуль) и дублирует снимок в `sessionStorage` —
запись отложенная, обновления склеиваются в одну, а при уходе со страницы снимок дописывается
сразу, чтобы не потерять хвост. Приложения, которые панелью не пользуются, за всё это не платят:
ни глобала, ни записей в `sessionStorage` не появляется вовсе.

Разбудить сбор на стенде можно тем же ключом, которым включается панель:

```js
localStorage.setItem('arui:devtools', '1');
location.reload();
```

В dev-сборке сбор включён всегда — там панель должна работать из коробки.

## В тестах

«Прод» для сбора — только сборка с `NODE_ENV=production`. В jest эта переменная равна `test`,
поэтому в юнит-тестах, где зовётся `createModuleLoader`, сбор работает: появляется глобал
`__ARUI_DEVTOOLS__`, а на каждое обновление стора планируется отложенная запись
в `sessionStorage`. Тестам это обычно не мешает, но становится заметно, если они проверяют
чистоту глобалов, снапшотят `sessionStorage` или строго считают таймеры с фейковыми часами.

Выключается тем же ключом, что и везде. В окружении `jsdom` достаточно setup-файла jest:

```js
// jest.setup.js (подключается через setupFiles)
localStorage.setItem('arui:devtools', 'off');
```

Решение кешируется при первом же репорте, поэтому ключ должен быть выставлен до первой
загрузки модуля — setup-файл для этого подходит.

## Вкладка «Модули»

Таблица попыток загрузки, свежие сверху. Одна строка — одна попытка, включая повторные загрузки
того же модуля.

| Колонка   | Что показывает                                                                                                    |
| --------- | ----------------------------------------------------------------------------------------------------------------- |
| Статус    | `грузится`, `загружен`, `ошибка`, `размонтирован`                                                                 |
| Модуль    | `moduleId`. Пометка «прошлая загрузка» — запись восстановлена из `sessionStorage` от предыдущей загрузки страницы |
| Версия    | Версия модуля из манифеста                                                                                        |
| Container | Имя module federation контейнера                                                                                  |
| baseUrl   | Эффективный адрес провайдера, уже после всех подмен                                                               |
| Режим     | `default`, `compat` или `из кеша`, если ресурсы взяты из кеша загрузчика                                          |
| Время     | От начала первой стадии до конца последней; пока модуль грузится — прочерк                                        |

Строка раскрывается по клику: `hostAppId`, share scope, url манифеста, водопад стадий, списки
скриптов и стилей с данными Resource Timing, а при ошибке — стадия, сообщение и стек.

### Что значит каждая стадия

Названия стадий — внутренняя терминология загрузчика, половина из них приходит из module
federation. В панели расшифровка открывается по иконке `i` рядом с названием стадии, а целиком
выглядит так:

| Стадия            | Что происходит                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------------------- |
| `fetch-manifest`  | Загрузка манифеста провайдера (`webpack-assets.json`) — из него берутся адреса скриптов и стилей   |
| `fetch-resources` | Скрипты и стили модуля вставляются в документ, загрузчик ждёт, пока браузер их загрузит            |
| `init-sharing`    | `__webpack_init_sharing__` — хост кладёт свои общие библиотеки в share scope                       |
| `container-init`  | `container.init()` — контейнер провайдера получает скоуп и добавляет туда свои версии библиотек    |
| `container-get`   | `container.get()` — у контейнера запрашивается фабрика нужного модуля                              |
| `factory`         | Вызов фабрики: код модуля исполняется и отдаёт свои экспорты                                       |
| `compat-get`      | Compat-модуль берётся из `window`: его скрипт при загрузке сам положил туда свой глобал            |
| `mount`           | Вызов `mount()` у модуля: модуль рисует себя в переданный элемент                                  |

Четыре стадии module federation — `init-sharing`, `container-init`, `container-get` и `factory` —
есть только у модулей в режиме `default`. У compat-модуля вместо них одна `compat-get`: он берётся
из `window`, и module federation в его загрузке не участвует. Паузы между полосками в водопаде —
это время, которое модуль ждал приложение, а не грузился. Незавершённая стадия тянется до
текущего момента, и пока запись на экране, водопад дорисовывает себя сам — рядом растёт её время
«не завершилась, …», по которому видно, на чём модуль висит и как долго.

**Про размер ресурсов.** Если рядом с ресурсом нет размера, это не «0 байт», а «браузер не сказал».
Для кросс-доменных ресурсов `transferSize` зануляется, пока провайдер не отдаст заголовок
`Timing-Allow-Origin`. Панель в таком случае показывает только длительность и не выдумывает размер.

**Про стадию `mount`.** Загрузчик умеет замерять её не для всех модулей: те, что разворачиваются
позже (`ServerStateModule`, `ModuleAbstract`), до замера не доходят. В подробностях такой записи
написано «стадия mount не измерялась» — это честнее, чем показать ноль.

## Вкладка «События»

Лог загрузчика: то, чего не видно в таблице модулей — **порядок событий между модулями**. Кто кого
ждал, что грузилось параллельно, на каком шаге всё встало.

Свежие сверху. Время отсчитывается от начала загрузки страницы; у записей, восстановленных
из предыдущей загрузки, своё начало отсчёта, поэтому в колонке времени у них прочерк.

Есть фильтр по модулю, типу события и тексту сообщения и чекбокс «Только ошибки». Счётчик справа
показывает, сколько записей осталось после фильтра.

Типы событий совпадают с теми, что лежат в контракте (`load-start`, `stage-start`, `stage-end`,
`error`, `load-end`, `unmount`) — по ним удобно искать и в снимке из консоли.

## Вкладка «Share scope»

Снимок того, что реально лежит в `__webpack_share_scopes__` на текущий момент: пакет, версии,
какой контейнер их положил, флаги `loaded` / `eager` / `singleton` и `requiredVersion`.

Подсвечиваются две ситуации, а их количество выносится в заголовок вкладки:

-   **несколько версий одного пакета в скоупе** — потребители могут получить разные копии;
-   **`singleton` с разными мажорами** — кто-то получит несовместимую версию.

### Чего на этой вкладке не видно

В рантайме share scope хранит только то, что в него **положили**. Требования потребителей
(`requiredVersion`, `strictVersion` из их consume-shared конфигов) в скоуп не попадают.

Практический пример: хост объявляет `react: '^18.0.0'`, провайдер — `react: '^17.0.0'`, а физически
установлен один и тот же `react@18.3.1`. В скоупе будет **одна** запись с `requiredVersion: '^18.0.0'`
от хоста, и расхождение требований останется невидимым. Панель тут ничего не скрывает — этих данных
в рантайме просто нет.

Чтобы такие расхождения стали видны, объявленные требования должен складывать в стор сам загрузчик.
Пока он этого не делает, и вкладка показывает только то, что реально лежит в скоупе.

## Если панели нет

-   **Нет бейджа в dev.** Проверьте, что `devtools` не выставлен в `'off'`, что не включён
    `disableModulesSupport`, и что в `localStorage` нет ключа `arui:devtools` со значением `off`.
    Бейдж появляется только после первой попытки загрузить модуль — если модулей на странице
    ещё не было, откройте панель хоткеем `Ctrl/Cmd+Shift+M`.
-   **Нет бейджа на стенде.** Прод-сборка с `devtools: 'dev'` не содержит кода панели вовсе.
    Нужен `devtools: 'always'` и пересборка.
-   **В логе сборки предупреждение «пакет `@alfalab/scripts-devtools` не найден или не собран».**
    Пакет приезжает зависимостью `arui-scripts`; такое бывает после ручной правки `node_modules`
    или при работе из монорепозитория без сборки пакетов. Панель в бандл не попадёт, но сборка
    приложения не упадёт.
-   **Панель открылась, но пишет «Ждём загрузчик модулей».** Стор появляется при первой попытке
    загрузить модуль. Если модулей на странице нет, ждать нечего.
-   **На стенде панель открылась, но осталась пустой.** В прод-сборке сбор данных спит и
    просыпается по тому же ключу `arui:devtools`, а читается ключ один раз при старте страницы —
    выставьте его и перезагрузитесь.
-   **Панель пишет про несовместимую версию стора.** Версии контракта у `@alfalab/scripts-modules`
    и `@alfalab/scripts-devtools` разошлись — обновите тот, что старше.

## Данные без панели

Всё, что показывает панель, лежит в глобальном объекте и доступно из консоли — панель не является
единственным способом до них добраться:

```js
__ARUI_DEVTOOLS__.modules.getSnapshot();
```

Это публичный версионированный контракт, его наполняет `@alfalab/scripts-modules`. Читать его может
кто угодно: панель, расширение браузера, ваш собственный код мониторинга.

```ts
type AruiDevtools = {
    /** версия оболочки глобала, меняется только несовместимо */
    readonly version: 1;
    /** неймспейс загрузчика модулей, появляется при первой попытке загрузить модуль */
    modules?: AruiModulesDevtools;
};

type AruiModulesDevtools = {
    /** версия контракта неймспейса, меняется только несовместимо */
    readonly version: 1;
    /** текущий снимок; ссылка меняется только когда данные поменялись */
    getSnapshot(): DevtoolsSnapshot;
    /** подписка на изменения, возвращает функцию отписки */
    subscribe(listener: () => void): () => void;
};

type DevtoolsSnapshot = {
    version: 1;
    /** записи о загрузках, кольцевой буфер на 50 записей */
    loads: ModuleLoadRecord[];
    /** лог событий, кольцевой буфер на 300 записей */
    events: DevtoolsEvent[];
};
```

Правила для тех, кто читает контракт:

-   глобала может не быть вовсе, и неймспейса в нём тоже — обе ситуации нормальные;
-   обязательно проверяйте `version` (и оболочки, и неймспейса) и деградируйте, если она незнакомая;
-   в сторе только сериализуемые данные — ссылок на экспорты модулей и DOM-ноды там нет и не будет.

Полные типы записей (`ModuleLoadRecord`, `DevtoolsEvent`, стадии и тайминги) экспортируются из
`@alfalab/scripts-modules`, а их копия на чтение — из `@alfalab/scripts-devtools`.

Снимок дублируется в `sessionStorage` под ключом `arui:devtools:modules`, поэтому записи переживают
перезагрузку страницы — в таблице они помечены как «прошлая загрузка».

Глобал создаётся только когда сбор включён: в прод-сборке без ключа `arui:devtools` его
не будет вовсе, поэтому читателям обязательно проверять наличие — см. [Цена в проде](#цена-в-проде).
