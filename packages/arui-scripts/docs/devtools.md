# Расширение для отладки модулей

Когда модуль не загрузился, а в консоли только `Failed to load module`, разбираться приходится
по крупицам: откуда его вообще пытались взять, какой манифест прочитали, дошло ли дело до
module federation, что лежит в share scope. Расширение показывает всё это в одном месте —
вкладкой **ARUI** в Chrome DevTools.

![Вкладка ARUI в DevTools](https://raw.githubusercontent.com/core-ds/arui-scripts/master/packages/arui-scripts-devtools/docs/panel-modules.png)

## Как поставить

Расширение живёт в репозитории и пока не выложено в магазин — ставится из папки:

```bash
yarn workspace @alfalab/scripts-devtools build
```

Дальше в Chrome: `chrome://extensions` → включить **Режим разработчика** →
**Загрузить распакованное расширение** → выбрать `packages/arui-scripts-devtools/build/extension`.

После этого в DevTools любой страницы появляется вкладка **ARUI**. Ничего подключать
в приложение не нужно: расширение читает данные, которые загрузчик модулей публикует сам.

### Какие права оно просит

При установке — никаких: доступ к странице расширению не нужен, данные оно получает через
`chrome.devtools.inspectedWindow.eval`, а это часть API самих DevTools.

Доступ к конкретному origin запрашивается ровно в тот момент, когда вы включаете
[подмену](#вкладка-подмена), и только к тому адресу, который подменяете. Не пользуетесь
подменой — расширение так и остаётся без прав на страницы.

## Что нужно от приложения

Только `@alfalab/scripts-modules` — тот же пакет, которым приложение грузит модули.
Диагностику он собирает сам, в бандл приложения ничего дополнительного не попадает.

В dev-сборке сбор включён всегда. В прод-сборке он спит и просыпается ключом в `localStorage`:

```js
localStorage.setItem('arui:devtools', '1');
location.reload();
```

Этим же ключом сбор выключается (`'off'`), если он мешает — например, в юнит-тестах.
Подробнее — в разделах [Цена в проде](#цена-в-проде) и [В тестах](#в-тестах).

## Цена в проде

Данные собирает `@alfalab/scripts-modules`: сбор живёт внутри загрузчика модулей.

В прод-сборке сбор по умолчанию **спит**. Он стоит на горячем пути загрузки каждого модуля
(больше трёх десятков обновлений стора на один модуль) и дублирует снимок в `sessionStorage` —
запись отложенная, обновления склеиваются в одну, а при уходе со страницы снимок дописывается
сразу, чтобы не потерять хвост. Приложения, которые расширением не пользуются, за всё это
не платят: ни глобала, ни записей в `sessionStorage` не появляется вовсе.

Разбудить сбор на стенде можно ключом `arui:devtools` в `localStorage` — см. выше.
В dev-сборке сбор включён всегда.

## В тестах

«Прод» для сбора — только сборка с `NODE_ENV=production`. В jest эта переменная равна `test`,
поэтому в юнит-тестах, где зовётся `createModuleLoader`, сбор работает: появляется глобал
`__ARUI_DEVTOOLS__`, а на каждое обновление стора планируется отложенная запись
в `sessionStorage`. Тестам это обычно не мешает, но становится заметно, если они проверяют
чистоту глобалов, снапшотят `sessionStorage` или строго считают таймеры с фейковыми часами.

Выключается тем же ключом, что и везде. В окружении `jsdom` достаточно setup-файла jest:

```js
// jest.setup.js (подключается через setupFiles)
localStorage.setItem('arui:devtools', 'off');
```

Решение кешируется при первом же репорте, поэтому ключ должен быть выставлен до первой
загрузки модуля — setup-файл для этого подходит.

## Вкладка «Модули»

Таблица попыток загрузки, свежие сверху. Одна строка — одна попытка, включая повторные загрузки
того же модуля.

| Колонка   | Что показывает                                                                                                    |
| --------- | ----------------------------------------------------------------------------------------------------------------- |
| Статус    | `грузится`, `загружен`, `ошибка`, `размонтирован`                                                                 |
| Модуль    | `moduleId`. Пометка «прошлая загрузка» — запись восстановлена из `sessionStorage` от предыдущей загрузки страницы |
| Версия    | Версия модуля из манифеста                                                                                        |
| Container | Имя module federation контейнера                                                                                  |
| baseUrl   | Эффективный адрес провайдера, уже после всех подмен                                                               |
| Режим     | `default`, `compat` или `из кеша`, если ресурсы взяты из кеша загрузчика                                          |
| Время     | От начала первой стадии до конца последней; пока модуль грузится — прочерк                                        |

Над таблицей — фильтр по модулю, контейнеру, адресу и статусу: искать в полусотне записей глазами
незачем.

Строка раскрывается по клику: `hostAppId`, share scope, url манифеста, водопад стадий, списки
скриптов и стилей с данными Resource Timing, а при ошибке — стадия, сообщение и стек. Кадры стека
с адресом кликабельны: открывают файл во вкладке Sources на нужной строке.

### Что значит каждая стадия

Названия стадий — внутренняя терминология загрузчика, половина из них приходит из module
federation. В панели расшифровка открывается по иконке `i` рядом с названием стадии, а целиком
выглядит так:

| Стадия            | Что происходит                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------------------- |
| `fetch-manifest`  | Загрузка манифеста провайдера (`webpack-assets.json`) — из него берутся адреса скриптов и стилей   |
| `fetch-resources` | Скрипты и стили модуля вставляются в документ, загрузчик ждёт, пока браузер их загрузит            |
| `init-sharing`    | `__webpack_init_sharing__` — хост кладёт свои общие библиотеки в share scope                       |
| `container-init`  | `container.init()` — контейнер провайдера получает скоуп и добавляет туда свои версии библиотек    |
| `container-get`   | `container.get()` — у контейнера запрашивается фабрика нужного модуля                              |
| `factory`         | Вызов фабрики: код модуля исполняется и отдаёт свои экспорты                                       |
| `compat-get`      | Compat-модуль берётся из `window`: его скрипт при загрузке сам положил туда свой глобал            |
| `mount`           | Вызов `mount()` у модуля: модуль рисует себя в переданный элемент                                  |

Четыре стадии module federation — `init-sharing`, `container-init`, `container-get` и `factory` —
есть только у модулей в режиме `default`. У compat-модуля вместо них одна `compat-get`: он берётся
из `window`, и module federation в его загрузке не участвует. Паузы между полосками в водопаде —
это время, которое модуль ждал приложение, а не грузился. Незавершённая стадия тянется до
текущего момента, и пока запись на экране, водопад дорисовывает себя сам — рядом растёт её время
«не завершилась, …», по которому видно, на чём модуль висит и как долго.

**Про размер ресурсов.** Если рядом с ресурсом нет размера, это не «0 байт», а «браузер не сказал».
Для кросс-доменных ресурсов `transferSize` зануляется, пока провайдер не отдаст заголовок
`Timing-Allow-Origin`. Панель в таком случае показывает только длительность и не выдумывает размер.

**Про стадию `mount`.** Загрузчик умеет замерять её не для всех модулей: те, что разворачиваются
позже (`ServerStateModule`, `ModuleAbstract`), до замера не доходят. В подробностях такой записи
написано «стадия mount не измерялась» — это честнее, чем показать ноль.

## Вкладка «События»

Лог загрузчика: то, чего не видно в таблице модулей — **порядок событий между модулями**. Кто кого
ждал, что грузилось параллельно, на каком шаге всё встало.

Свежие сверху. Время отсчитывается от начала загрузки страницы; у записей, восстановленных
из предыдущей загрузки, своё начало отсчёта, поэтому в колонке времени у них прочерк.

Есть фильтр по модулю, типу события и тексту сообщения и чекбокс «Только ошибки». Счётчик справа
показывает, сколько записей осталось после фильтра.

Типы событий совпадают с теми, что лежат в контракте (`load-start`, `stage-start`, `stage-end`,
`error`, `load-end`, `unmount`) — по ним удобно искать и в снимке из консоли.

## Вкладка «Таймлайн»

Все загрузки страницы на одной оси времени. Водопад внутри строки отвечает, что заняло время
у конкретного модуля; здесь виден другой, межмодульный вопрос: что грузилось параллельно,
а что выстроилось в очередь за чужой загрузкой.

Цвет полоски — статус загрузки, длина — от первой засечки до последней. Незавершённые загрузки
тянутся до текущего момента и дорисовываются сами. Записи предыдущей загрузки страницы сюда
не попадают: у них своё начало отсчёта, и на общей оси они оказались бы где угодно.

## Вкладка «Event bus»

События `@alfalab/client-event-bus`: какая шина, какое событие, сколько слушателей его получили
и с какой нагрузкой. Отдельной строкой — подписки, до которых не дошло ни одного события.

Главное, ради чего вкладка нужна: строка со слушателями `0` — это событие, ушедшее в пустоту.
Отправили, а подписчиков не было; из кода это обычно выясняют логами.

Нагрузка приводится к сериализуемому виду: в шину кладут что угодно, а в контракте могут
жить только данные. Функции и циклические структуры показываются описанием, слишком длинные —
обрезаются.

## Вкладка «Подмена»

Перенаправление адреса провайдера на локальный дев-сервер: правите модуль у себя — видите его
в реальном хосте на стенде, не собирая и не выкладывая. Меняются только схема, хост и порт,
путь модуля остаётся прежним.

Права на origin расширение просит в момент включения подмены, а не при установке: пока подменой
не пользуются, оно не имеет доступа ни к одной странице. Правила живут в сессии браузера —
перезапуск Chrome их снимает, и забытая подмена не переживёт день.

## Вкладка «Share scope»

Снимок того, что реально лежит в `__webpack_share_scopes__`: пакет, версии, какой контейнер их
положил, флаги `loaded` / `eager` / `singleton` и `requiredVersion`.

Снимок кладёт в контракт сам загрузчик (поле `shareScopes`), а не панель. Иначе и быть не может:
`__webpack_share_scopes__` — свободная переменная бандлера, её не видно ни из консоли, ни из
расширения браузера, ни из любого кода за пределами того бандла, куда её подставил rspack.
Пересобирается снимок в начале и в конце каждой загрузки модуля — там скоуп и меняется:
хост кладёт свои библиотеки на `init-sharing`, провайдер добавляет свои на `container-init`.

Подсвечиваются две ситуации, а их количество выносится в заголовок вкладки:

-   **несколько версий одного пакета в скоупе** — потребители могут получить разные копии;
-   **`singleton` с разными мажорами** — кто-то получит несовместимую версию.

### Кто что просит

Рядом с именем пакета видно все объявленные требования — и приложения, и каждого провайдера:
`приложение просит ^18.0.0`, `example_modules просит ^17.0.0`. Если ни одна версия в скоупе
не подходит под чьё-то требование, вкладка называет пострадавшего отдельной проблемой.

Именно здесь виден самый неприятный случай микрофронтов: в скоупе одна версия, хосту она
подходит, а провайдер тихо получает собственную копию библиотеки — и на странице оказывается
два React.

Данные приходят не из скоупа: в рантайме требований нет нигде — скоуп хранит только то,
что в него положили. Требования приложения `arui-scripts` подставляет в бандл на сборке,
а требования провайдера едут в его манифесте (`__metadata__.sharedRequirements`) и попадают
в контракт, когда загрузчик этот манифест скачивает. Провайдер, собранный старой версией
`arui-scripts`, своих требований не покажет.

Сверка нарочно грубая — по мажору: полноценный semver стоил бы пакету зависимости, а ломается
совместимость именно на мажоре. Диапазоны, которые не разобрались (`*` и подобные), считаются
удовлетворёнными: ложная тревога здесь хуже молчания.

## Если данных нет

-   **Вкладки ARUI нет в DevTools.** Расширение не установлено или установлено из старой сборки:
    пересоберите (`yarn workspace @alfalab/scripts-devtools build`) и нажмите «Обновить»
    на карточке расширения в `chrome://extensions`. DevTools после этого надо закрыть и открыть
    заново — вкладки заводятся при их запуске.
-   **Вкладка есть, но пишет «Ждём загрузчик модулей».** Стор появляется при первой попытке
    загрузить модуль. Если модулей на странице нет, ждать нечего.
-   **На стенде вкладка пустая.** В прод-сборке сбор спит и просыпается по ключу `arui:devtools`,
    а читается ключ один раз при старте страницы — выставьте его и перезагрузитесь.
-   **Расширение пишет про несовместимую версию стора.** Версии контракта у
    `@alfalab/scripts-modules` и у расширения разошлись — обновите то, что старше.
-   **Вкладка «Share scope» пуста, хотя модули грузятся.** Снимок скоупа кладёт в контракт
    загрузчик, и умеет это только `@alfalab/scripts-modules` свежее той версии, где появилось
    поле `shareScopes`. На старом загрузчике показывать нечего.

## Данные без расширения

Всё, что показывает расширение, лежит в глобальном объекте и доступно из консоли — расширение
не является единственным способом до них добраться:

```js
__ARUI_DEVTOOLS__.modules.getSnapshot();
```

Это публичный версионированный контракт, его наполняет `@alfalab/scripts-modules`. Читать его может
кто угодно: расширение, ваш собственный код мониторинга.

```ts
type AruiDevtools = {
    /** версия оболочки глобала, меняется только несовместимо */
    readonly version: 1;
    /** неймспейс загрузчика модулей, появляется при первой попытке загрузить модуль */
    modules?: AruiModulesDevtools;
};

type AruiModulesDevtools = {
    /** версия контракта неймспейса, меняется только несовместимо */
    readonly version: 1;
    /** текущий снимок; ссылка меняется только когда данные поменялись */
    getSnapshot(): DevtoolsSnapshot;
    /** подписка на изменения, возвращает функцию отписки */
    subscribe(listener: () => void): () => void;
};

type DevtoolsSnapshot = {
    version: 1;
    /** записи о загрузках, кольцевой буфер на 50 записей */
    loads: ModuleLoadRecord[];
    /** лог событий, кольцевой буфер на 300 записей */
    events: DevtoolsEvent[];
    /** содержимое share scope на момент последнего события загрузки */
    shareScopes: DevtoolsShareScope[];
    /** кто что объявил в modules.shared: приложение — из сборки, провайдеры — из манифестов */
    sharedRequirements: Record<string, DevtoolsSharedRequirement[]>;
};
```

Правила для тех, кто читает контракт:

-   глобала может не быть вовсе, и неймспейса в нём тоже — обе ситуации нормальные;
-   обязательно проверяйте `version` (и оболочки, и неймспейса) и деградируйте, если она незнакомая;
-   в сторе только сериализуемые данные — ссылок на экспорты модулей и DOM-ноды там нет и не будет.

Полные типы записей (`ModuleLoadRecord`, `DevtoolsEvent`, стадии и тайминги) экспортируются из
`@alfalab/scripts-modules`.

Снимок дублируется в `sessionStorage` под ключом `arui:devtools:modules`, поэтому записи переживают
перезагрузку страницы — в таблице они помечены как «прошлая загрузка».

Глобал создаётся только когда сбор включён: в прод-сборке без ключа `arui:devtools` его
не будет вовсе, поэтому читателям обязательно проверять наличие — см. [Цена в проде](#цена-в-проде).
